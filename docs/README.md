# riot-proxy documentation

riot-proxy is the single Rust binary that stands between the ninjagoldfinch.lol platform and the Riot Games API. It holds the one Riot key, stays inside Riot's rate limits, caches what can be cached, archives every match and timeline it sees, crawls the ranked ladder, turns the archive into champion analytics, and issues the consumer keys the website and the operator use. It runs beside the website on one Onidel Sydney VPS, keeps its state in one SQLite file, and offloads raw match bodies to an S3 bucket mirrored to Cloudflare R2. This set describes what is built at version 2.7.0; the design it implements lives in [design/](./design/README.md) and the decisions in [DECISIONS.md](./DECISIONS.md).

`workflows/adding-a-page.md` from the original outline does not apply: riot-proxy serves no pages beyond its three embedded developer and operator pages, whose rules are in `design/10-dev-explorer.md`, `design/11-showcase.md` and `design/13-admin-dashboard.md`. ## Conventions

- Everything stated here is traceable to the repository; each page ends with a `Sources` line (files and line ranges) and a `Last verified` date and commit.
- Unknowns are marked `> **TODO (unverified):** …` so they can be found with one grep; they are collected in [_meta/gaps.md](./_meta/gaps.md).
- Diagrams are Mermaid with consistent names: `Browser`, `ninjagoldfinch.lol`, `riot-proxy`, `ninja-monitor`, `Riot API`, `Cache`, `DB`, `Onidel Object Storage`, `Cloudflare R2`, `GitHub Actions`.
- British/NZ spelling, present tense, numbered steps for procedures.
